# Hiking Book

An interactive ebook of our hikes: one page per hike with a map, a
slope-colored elevation profile, stats and a photo gallery.

```
HikingBook/
  hikes/                  ← the content: one folder per hike
    <hike_id>/
      track.gpx           route (komoot export works fine)
      hike.json           title, date, description, captions, …
      photos/             original photos (jpg/png/webp, any size)
  backgrounds/            photos used as the blurred page background
  tools/                  ← Python: turns hikes/ into website data
    build_hikes.py
    new_hike.py
    hikebook/             gpx reading, metrics, photo resizing
  web/                    ← Vite website (the ebook itself)
    index.html            list of all hikes
    hike.html             one page for every hike (hike.html?id=<hike_id>)
    src/                  JS + CSS  (src/config.js = colors, units, …)
    public/data, public/photos   generated by build_hikes.py, don't edit
```

## First-time setup (Windows, from the HikingBook folder)

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r tools\requirements.txt

cd web
npm install
```

## Adding a hike

1. `python tools\new_hike.py C:\path\to\Some_Hike.gpx`
   → creates `hikes\some_hike\` with `track.gpx`, `hike.json` and `photos\`
2. Drop photos into `hikes\some_hike\photos\` (they're shown in filename order).
3. Fill in `hike.json` (see below).
4. `python tools\build_hikes.py` (or `npm run data` inside `web\`)
5. `cd web` → `npm run dev` → open http://127.0.0.1:5180
   - On your phone (same Wi-Fi): `npm run dev:phone` instead, then open the "Network:" address it prints (e.g. http://192.168.1.23:5180). Your location doesn't work there (phones only share it over https).

Rerun step 4 whenever you change a hike. Photos that are already resized are skipped, so it stays fast.

## hike.json

```json
{
  "title": "Watzmann Umrundung",
  "date": "2025-08-23",
  "location": "Berchtesgaden, Germany",
  "description": "First paragraph…\n\nSecond paragraph…",
  "companions": ["Anna", "Max"],
  "difficulty": "Hard",
  "cover": "IMG_1234.jpg",
  "captions": {
    "IMG_1234.jpg": "Sunrise at the Königssee",
    "IMG_1240.jpg": "Lunch at Kärlingerhaus"
  },
  "draft": false
}
```

| field | notes |
|---|---|
| `title` | empty → name from the GPX file |
| `date` | `YYYY-MM-DD`; empty → first timestamp in the GPX. The index is sorted newest first. |
| `description` | blank line (`\n\n`) = new paragraph |
| `cover` | your main photo for this hike (header, index card and page background); empty → a generated landscape drawn from the hike's elevation profile |
| `captions` | keyed by photo filename; photos without one just have no caption |
| `draft` | `true` hides the hike from the book |

Distance, ascent/descent, highest point and duration are calculated from
the GPX, so you never type them by hand.

## Background photos

Drop any landscape photos into `backgrounds\` and rerun `build_hikes.py`.
A hike page uses its own cover photo as the blurred background; hikes without
photos get one of the `backgrounds\` photos (always the same one per hike).
The index page uses `indexBackground` from `web/src/config.js`.

## Website settings

`web/src/config.js` has the units (`'metric'` or `'imperial'`), the background
(`backdrop`, `indexBackground`, `backdropBlur`), the colors and the slope-color scale.

## Building the finished book

```powershell
python tools\build_hikes.py
cd web
npm run build      # → web\dist\  (a static site, works from any folder or host)
npm run preview    # check the built version
```

## Installing, offline use and location

The built site is an installable app ("PWA"):

- **Install:** on Android/Chrome/Edge an *Install* button appears on the index page.
  On iPhone/iPad: Share → *Add to Home Screen* (the button explains this).
- **Offline:** every page, hike and photo you open is kept on the device
  (`web/public/sw.js`). On a hike page, *Save for offline* also stores all its
  photos and the map around the trail, so it works without signal.
- **Location:** the ◎ button on the map shows a blue dot, the same spot on the
  elevation profile and how far along the trail you are. GPS works offline; the
  map background only where it was saved.

Browsers only allow offline mode and location on `https://` sites or on your own
computer (`localhost`). To try it locally:

```powershell
cd web
npm run build
npm run preview      # → http://127.0.0.1:4180
```

On a phone it needs the published (https) version.

The ports (5180 dev, 4180 preview) are deliberately different from Hitster's:
a service worker belongs to an address, so two apps on the same port would
show each other's cached pages.
`npm run dev` skips offline mode on purpose (it would cache files you're editing);
location still works there.

After a big change, bump `VERSION` at the top of `web/public/sw.js` so
everyone's app picks up the new pages.

## Publishing (GitHub Pages, for now)

```powershell
cd web
npm run deploy     # runs build_hikes.py + vite build, then pushes web\dist\ to the gh-pages branch
```

The site appears at https://gerggz.github.io/dn-trails/ (GitHub serves the
`gh-pages` branch; `main` stays the source). One-time setup: `npm install` in
`web\`, the `dn-trails` repo set to **public** (free accounts only get Pages for
public repos), and in the repo's Settings → Pages: *Deploy from a branch* →
`gh-pages` / `(root)`. Everything on the site is public, so this is a temporary
home until private photos need Cloudflare Pages + Access.
